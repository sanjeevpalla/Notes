### 7. Stage 2 — Planning, Part 2: The Seven Migration Strategies, Properly Contextualized

#### 📖 Definition — Rehost ("Lift and Shift")

> 💡 **Given directly:** *"Rehost is basically lift and shift — with very minimalistic effort, or with zero percent effort, you will take this microservices from your on-premises cloud and deploy on the AWS cloud... you will create the same Kubernetes cluster, same type, and on top of that you will deploy those applications — literally there is no change, except these applications are on your public cloud now."*

```mermaid
flowchart LR
    A["An On-<br/>Premises<br/>Environment (e.g.<br/>a Kubernetes<br/>CLUSTER)"] --> B["REHOST: RECREATE<br/>the EXACT, same<br/>environment ON<br/>AWS -- MINIMAL,<br/>near-ZERO<br/>MODIFICATION"]
```

#### 📖 Definition — Replatform

> 💡 **Given directly:** *"As part of replatform, what you will try to do is you will try to add some little changes — once you decide to move your applications onto AWS cloud platform, you will take advantage of this AWS platform... instead of creating this Kubernetes cluster in one region, you can create the control plane in multiple regions, so that you can achieve high availability."*

```mermaid
flowchart LR
    A["Rehost (LIFT<br/>and SHIFT)"] --> B["PLUS: a FEW,<br/>SELECTIVE AWS-<br/>specific<br/>IMPROVEMENTS (e.g.<br/>MULTI-region<br/>control PLANE, for<br/>HIGH<br/>availability)"]
    B --> C["= Replatform"]
```

#### 📖 Definition — Refactor / Re-Architecture

> 💡 **Given directly:** *"Refactor model is very, very suitable in this example — let's say you are using monolithic applications, so these have to be converted to microservices, and when that has to be converted, you have to re-architect your application... you will explore for the latest and new technologies, and go with the best things that are available on AWS."*

```mermaid
flowchart LR
    A["A Monolithic<br/>Application"] --> B["REFACTOR: FULLY<br/>re-architected<br/>INTO microservices<br/>-- USING the<br/>BEST, latest,<br/>AWS-native TOOLS<br/>and APPROACHES"]
```

#### ⚠ Common Mistakes

* Assuming REHOST, replatform, AND refactor are GENUINELY, EQUALLY simple, INVOLVING the SAME degree OF effort — explicitly, directly, PRECISELY distinguished: THEY represent a GENUINE, real SPECTRUM — from MINIMAL effort (REHOST) to SUBSTANTIAL, architectural CHANGE (refactor).

#### 🎯 Key Takeaways

* **REHOST ("lift AND shift")**: MINIMAL effort — RECREATING the EXACT, SAME environment ON AWS, WITHOUT any, GENUINE modification.
* **REPLATFORM**: rehost PLUS a FEW, SELECTIVE AWS-specific IMPROVEMENTS (e.g., multi-REGION control PLANE, for HIGH availability).
* **REFACTOR/re-architecture**: the MOST involved — FULLY converting a MONOLITHIC application INTO microservices, USING the BEST, latest AWS-native TOOLS and APPROACHES.
